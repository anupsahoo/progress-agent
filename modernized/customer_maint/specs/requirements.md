# Requirements — customer_maint.p

## Intent
Modernize Customer Maintenance to a web UI + REST API. **Behaviour must be identical to the legacy program.**

## Functional requirements
| ID | Requirement (EARS) | Source line |
|----|--------------------|-------------|
| R1 | WHEN a user enters a customer number THE SYSTEM SHALL look up the customer by `CustNum`. | `FIND FIRST Customer WHERE Customer.CustNum = iCustNum` |
| R2 | IF no customer matches THEN THE SYSTEM SHALL show the error "Customer not found." | `MESSAGE "Customer not found."` |
| R3 | WHEN a customer is found THE SYSTEM SHALL display CustNum read-only and allow editing Name, Address, City, State, PostalCode, Phone. | `disp Customer.CustNum` / `update ...` |
| R4 | WHEN the user saves THE SYSTEM SHALL persist the edited fields and show "Record updated successfully." | `MESSAGE "Record updated successfully."` |
| R5 | WHILE a user is editing a record THE SYSTEM SHALL prevent conflicting concurrent updates. | `EXCLUSIVE-LOCK` |
| R6 | WHEN an edit session ends THE SYSTEM SHALL release any lock or version hold. | `RELEASE Customer.` |
| R7 | THE SYSTEM SHALL allow repeated lookups without restarting. | `REPEAT:` |

## Non-functional
- N1 Concurrency: pessimistic `EXCLUSIVE-LOCK` → optimistic concurrency (ETag / version). A stale save returns HTTP 409.
- N2 p95 lookup latency < 200 ms at 50 concurrent users.
- N3 Accessibility: WCAG 2.1 AA form labels and error announcements.
- N4 Audit: every update records user, timestamp, before/after values.
